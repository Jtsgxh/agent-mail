# 第一版验收记录

日期：2026-09-09。环境：Windows、本机 Node.js 24.18.0、Codex CLI 0.153.2、Claude Code 2.1.238。

## 自动化

`npm test` 验证持久化、阅读进度、定向通知、分页、幂等发送、暂停/恢复、断线后未确认消息重投、同一参与者重复连接拒绝、跨站请求拒绝、CLI 进程、Claude MCP 协议、Codex 状态切换及输出错误处理。还通过实际启动 CLI 子进程，验证了 Claude MCP stdio 初始化、工具发现与通知收取。

Codex 协议测试使用模拟 App Server；Claude 协议测试使用官方 MCP SDK，并不意味着真实 Claude 模型已经消费 Channel 事件。

## 真实 Codex

已运行 `scripts/smoke-codex.js`。独立 App Server 中创建的测试会话完成初始轮次并进入空闲，然后：

1. 发第一封定向消息，真实模型回复“第 1 次收信成功”，回信写入信箱，原消息确认。
2. 同一会话再次处于空闲，发第二封信，真实模型回复“第 2 次收信成功”，回信与确认成功。
3. 停止桥接、归档测试会话、关闭测试 App Server。

额外发现：临时、没有持久化记录的会话不能经 `thread/resume` 恢复。正式桥接要求已有可恢复的会话，不用猜测或复制会话状态绕过这个限制。

## 网页

使用 Codex 内置浏览器实际操作本机服务，检查空状态、创建主题、Markdown/代码块消息、创建参与者及连接说明、定向通知显示待投递、暂停/恢复、关闭后禁用发送、重新打开，以及人工确认已读。浏览器未报告 JavaScript 错误或警告。

## 尚未证明的部分

- 真实 Claude Code 在交互终端启用自定义 Channel 后，模型自动消费来信并回信。安装和协议实现已提供，需要在对应 Claude 会话中启用 Channel。
- 自动连接任意已经打开的 Codex 桌面或 CLI 窗口。第一版只连接用户明确提供的 App Server 地址和可恢复会话 ID。
- 多机、多用户认证隔离、自动启动 agent、自动恢复已经退出的 agent 进程，不属于本版本功能。
